# Tab｜无线电子纸教室课表终端：项目方案 V1.0

> 所属平台：MAC（Moonshot Academy Campus）  
> 文档状态：**设计方案 / 尚未完成系统或硬件验收**  
> 基线日期：2026-11-04  
> 执行进度：见 [PROGRESS.md](./PROGRESS.md)

## 1. 项目定位与边界

**Tab** 是安装在学校教室门口的实体电子纸课表终端；MAC 是既有校园平台和 Tab 的数据、预览及设备服务承载方。**MAC 网页预览只是硬件 MVP 的验证手段，不是 Tab 的最终交付形态。**

用户走近门口，应迅速确认：(1) 教室编号；(2) 今天有哪些课程及准确时间；(3) 当前正在上哪节，或者下一节是什么。

### 验收级产品约束

| 维度 | 要求 |
|---|---|
| 形态 | 无触控的实体电子纸设备，墙面可拆卸安装，3D 打印一体式视觉外壳 |
| 供电 | 门口不布线、不接固定外部电源；内部安全电池供电 |
| 续航 | **真实正常使用 ≥30×24 小时免充电**；设计争取 45–60 天余量 |
| 课表数据 | **SEIUE API / 固定课表** 两种明确可配置模式 |
| 可用性 | 当日所有有效课程必须完整可读，不以自动翻页或隐藏课程代替完整显示 |
| 操作 | 设备无需师生交互；课程、状态随时间与数据变化自动更新 |
| 规模 | 单台 MVP → 1–3 间教室试点 → 校园批量部署 |
| 产品外观 | 借鉴 Jony Ive 时代产品的一体性、克制和精密制造逻辑，不复刻 Apple 产品 |

**明确不做：** 教室预约、签到考勤、实时人数检测、学生画像、触控交互、公告广告系统、独立于 MAC 的另一个教务平台。

**推荐平台集成体验：** 用户在 MAC 地图选择教室 → 房间详情中可进入该教室的 **Tab 课表预览**（可采用单独的 `/tab` 或其他明确路由，实际路径由实现确定）→ 使用与设备相同的课程投影和显示布局。在房间搜索和地图中复用同一份 `room_id`，但**不把“有课/无课”直接转换为“有人/空闲”或“可预约”**。独立的直接预览入口可方便教务/研发测试，但不能把它当成 Tab 最终产品。

**平台责任边界：**
- **MAC 网站/服务端**：数据源授权、统一课表、教室和设备映射、预览与渲染、设备鉴权/版本、管理与监测；
- **Tab ESP32 终端**：定时唤醒、联网获取已授权画面、正确刷屏、缓存与深度休眠；
- **SEIUE**：仍是其所负责课程安排的权威来源；MAC/Tab 不回写希悦、不提供预约；
- **固定课表**：由明确的文件及例外记录维护，不能假称是学校实时教务数据。

**关键安全和部署限制：** 当前 MAC 以 Vite/React 前端加 Git-connected Cloudflare Pages 静态部署为主（见 [部署说明](../CLOUDFLARE_PAGES.md)）。现有 `/admin` 无登录且配置是本地存储；**不得将 SEIUE `client_secret`、设备长期凭证、真实课表管理写权限放入静态前端或公开 JSON 中**。真实线上数据同步与设备接口需要确认并配置安全的后端运行位置（例如同域 Pages Functions/Workers，或复用已有可信服务端），以及最小权限与管理员鉴权。该功能尚未验证，不得描述为已上线。

```text
SEIUE OpenAPI ──> SEIUE adapter ──┐
                                 ├─> MAC normalized schedule
CSV/JSON + weekly rules ─> Fixed adapter ─┘
                                          |
                                          v
                              validation / daily projection
                                          |
                                          v
                           screen renderer + revision manifest
                             /                         \
                        MAC preview                Tab device API
                                                       |
                                              ESP32 + e-paper
```

保留 MAC 现有 React/TypeScript/Vite 代码、路由和 UI 约定；当前仓库具有 Cloudflare Pages 相关配置。**服务端实现需先检查实际部署方式**，可使用现有服务端能力或兼容的 Pages Functions/Workers。不得假定 Vite 前端构建产物能够安全保存 API 密钥，也不得为 Tab 新建重型服务或单独的登录系统。

按需实现逻辑模块，不要求拆成微服务：
- **Room / Source Registry**：MAC 教室 ID、设备 ID、选定数据源及映射。
- **Source Adapters**：读取 SEIUE 或固定数据。
- **Normalizer / Validator**：统一课节、时区、异常及版本。
- **Daily Projection / State Engine**：今天的有效课程、上课中/下一节、日期状态。
- **Renderer**：先可在 MAC 浏览器预览；然后按面板实际分辨率输出硬件可解码图像。
- **Device Gateway**：版本检查、画面下载、最小心跳/状态。
- **Firmware**：显示、配网、睡眠、唤醒、离线恢复；不接触 SEIUE 密钥。

## 3. 双数据源：单一标准数据模型

### 3.1 每教室明确选源

`source_type=seiue|fixed`；同一教室、同一生效时段只允许一个正式来源。MAC 读取路径相同，Tab 固件与显示界面不区分来源。

禁止在 SEIUE 暂时不可用时，**自动切换至另一份固定课表**。故障情况下允许展示**同一数据源最近一次有效、带清晰日期和同步时间的缓存**，不能伪装为已确认的当天安排。

### 3.2 SEIUE（接入待授权与实测）

官方文档入口：https://open.seiue.com/docs/v3/ ；OAuth：https://open.seiue.com/docs/oauth.html

| API | 目的 | 必要性 |
|---|---|---|
| POST /api/v3/oauth/tokens | Client Credentials 换取 Token | 必须 |
| GET /api/v3/klass/rectangular-lessons | 指定教室及日期课节查询 | 必须 |
| GET /api/v3/place/places | 获取教室 ID 与名称 | 若学校不能直接提供 ID 才需要 |

配置字段：`client_id`、`client_secret`、`school_id`、测试教室 `place_id`、授权 `scope`；`semester_id` 可选。凭证只放在受控服务端秘密配置。业务调用携带 Bearer Token 与学校标识，按文档完成认证。

**必须向希悦/学校核实：** 课节接口准确 scope（文档相关示例出现 `klass.read` 与 `class.read`）、学校授权范围、真实响应字段/日期边界/时间格式、调课与取消如何呈现及同步延迟、限流/IP 白名单/费用、学校是否允许在门口公开教师名称等字段。未拿到真实响应前，不得把示例结构当成生产契约。

### 3.3 固定课表（不依赖希悦）

支持两种输入：
1. **日期事件表**：某日实际安排（测试周/临时活动），CSV 或 JSON。
2. **周重复课表**：周一至周日、起止时间、课程名、生效日期区间，遇到非教学日/节假日按明确规则处理。

提供例外覆盖：指定日期新增、取消、换房间，以及整个日期停课。**例外优先于每周模板**；同一时刻不得在不同地方重复记同一事件。每份固定课表必须记录版本、生效区间与最近更新来源。

当前对话中已经准备过 8 间教室、5 个教学日的模拟课表，用于测试；**这些数据尚未确认导入 MAC 仓库，不得视为当前生产真实排课。** 个人学生课表不能代表学校全部教室占用情况。测试数据应与真实数据明显区分。

### 3.4 统一课程事件（建议契约）

```ts
type ScheduleEvent = {
  event_id: string;
  room_id: string;             // MAC canonical room code
  date: string;                // YYYY-MM-DD, Asia/Shanghai
  start_time: string;          // HH:mm
  end_time: string;            // HH:mm
  title: string;
  status: 'scheduled' | 'cancelled' | 'moved_out';
  source: 'seiue' | 'fixed';
  teacher_name?: string;       // only when authorized for display
  origin_room_id?: string;
  destination_room_id?: string;
  updated_at?: string;
  revision?: string;
};
```

源数据可包含更多字段，但不得把 SEIUE 原始对象直接交给设备。投影时：
- 对课程按实际开始时间排序；同日时间段按 `[start,end)` 判断。
- `cancelled` / `moved_out` 不作为原教室有效占用，但需要时可生成清晰的变更提示。
- 调入后的有效课程显示在新教室；不能只删除原教室而漏记新教室。
- 重叠排课、缺字段、跨日、同名课程、时间格式错误须有显式处理或校验结果。
- 区分 **成功取得空课表**、**查询失败**、**数据已过期**，不把未知展示为无课。
- 记录 `source`、数据有效日期、`fetched_at`、版本 hash 以支持追溯。

## 4. 屏幕内容及显示状态

优先显示：**教室编号 > 当日全部有效课程（名称及起止时间） > 当前课程高亮 > 日期 > 变更/同步状态**。教师、年级及其他辅助文字只有在授权且屏幕容量允许时显示。

采用高对比黑白、白色大面积底色、极少分隔线和有序字重；不显示实时秒表、广告、预约按钮、动画和自动轮播。设备名称 Tab 主要用于产品/维护，不占据课表的显著位置。

布局规则需在真实面板上验证，而非假定已购面板一定为 800×480：
- 0 节：确认数据有效后显示“今日无课程安排”。
- 1–4 节：宽松单列；5–7 节：标准单列。
- 8–10 节：紧凑单列或双列，仍要能读清长课程名与时间。
- 若内容超出可读容量，**先触发版式/产品设计阻塞**，重新考虑字体、信息密度或物理屏幕尺寸；不得静默截断。
- 不把“目前没有排课”描述为“教室现在无人”或“可以预约”。

状态机：
- 上课前 → 突出下一节。
- 上课中 → 在全天列表直接强调当前课程。
- 课间 → 突出下一节。
- 当天结束 → 保留完整日程，标明结束。
- 取消/换房间 → 明确变更信息。
- 数据过期或失败 → 保留有效缓存并标记日期，必要时显示“日程待确认”。

**一个核心布局，不在各种状态之间轮播页面。** 变更时仅更新相关文字或强调，避免重复占用屏幕面积的“Now”大卡片。

## 5. 同步、图像传输和刷新机制

**三件事分离：** 数据源同步、设备获取版本、电子纸物理刷屏。

首个硬件 MVP：
1. MAC 生成当日课表和版本 hash。
2. MAC 浏览器预览与设备画面共享同一套课程投影逻辑。
3. ESP32 定时联网检查 manifest；版本有变化才下载适配的画面并刷屏。
4. 固件完成刷屏后进入合适的屏幕休眠与 ESP32 Deep Sleep。
5. 网络失败按退避策略重试；离线缓存保留日期和来源有效性，不提示虚假“无课”。

为实现**课程开始/结束时的高亮切换**，首版可在边界唤醒并联网请求状态画面；后续根据功耗结果决定是否预缓存一天内各边界时刻的画面，做到离线本地切换。不能一方面只缓存单张服务器生成图片，另一方面宣称无网即可任意切换课程。

**待测参数：** 教学时段每 15–30 分钟检查课表变化作为基准；若业务要求 5 分钟内体现临时调课，单独增加该测试工况并重新核算续航。实际同步 SLA 在学校确认前保持待定。课程时间边界、跨日及夏令时问题要基于统一的 `Asia/Shanghai` 时区和可靠时钟处理。

屏幕驱动：
- 以已购面板**准确驱动 IC/型号、分辨率、接口、电压**确认官方 Demo 后选择库。
- 候选 GxEPD2：https://github.com/ZinggJM/GxEPD2 ，仅在该面板明确兼容时使用。
- 默认先实现稳定全刷；局刷需证实支持并按面板要求清残影。
- 图像编码、内存需求、中文字体渲染策略必须由 ESP32 可用 Flash/PSRAM 和实际面板确定，避免盲目假设可直接下载 PNG。

## 6. 硬件、电池与 30 天硬门槛

**现有事实：** 已购 ESP32 + 电子纸面板；用户提供过面板背面照片。**尚未确认**开发板、驱动芯片、分辨率、烧录成功、电池/充电管理模块或真实功耗。

首轮流程：识别准确型号 → 官方 Demo 点亮 → MAC 图像显示 → 电池安全接入 → 睡眠/唤醒 → 功耗计量。

无门口布线；优先使用成熟、具备保护与充电管理的电池方案及 USB-C **拆卸后集中充电**。未经核实不能把电芯直接接到未知接口。需确认电池低压、充电过温、短路保护及运输/维护安全。

续航预算统一以电池侧平均消耗计算：对于假设的 **2000mAh 电池**，若仅按 60% 标称容量作为可用预算，30 天平均电流需 ≤约 1.67mA；45 天需 ≤约 1.11mA。此为设计演算，不代表已购设备具备 2000mAh 电池或已达标。

必测：深度休眠电流、单次启动/Wi-Fi/TLS 请求电量、全刷及局刷耗电、异常重连、低电量响应和实际可用电池容量。先用持续功耗记录分析，再按真实教室业务配置完成**至少连续 30 天整机无充电实测**。短期推算不能替代最终认证。

## 7. 工业设计、3D 打印与安装

外观原则：一体式连续圆角前壳、正面无可见紧固件、细致哑光表面、屏幕平整、侧面克制。与 MAC 平台视觉语言协调，但电子纸可采用独立的高对比黑白媒介排版。

结构建议：
- **Front shell**：3D 打印完整前框，后装屏幕，避免玻璃/电子纸受局部挤压。
- **Rear cover**：可维修，隐藏 USB-C、重启及电池检修。
- **Wall dock**：独立底座，滑轨/机械卡扣承重，磁吸仅用于定位，可设置防拆及防坠结构。

墙面固定方式依现场实物调查、消防/物业/设施许可、承重和墙面材质决定，不默认强力胶能在粗糙墙面长期可靠。原型可用 PETG 及参数化 CAD 打样，但在准确硬件尺寸和散热/电池间隙测量前不冻结壳体尺寸。结构验收包括多次装拆、跌落/防脱风险、日常擦拭、充电取放。

## 8. 安全、部署与设备管理

- SEIUE client secret 仅保留在 MAC 服务端；设备只持设备自身最低权限凭证。
- 使用 HTTPS；密钥不能进入静态前端、固件、截图、仓库或公开日志。
- 对设备端接口进行鉴权与绑定，禁止仅凭可猜的 room ID 访问敏感数据或操作设备。
- 初版最小健康状态：设备 ID、教室映射、固件版本、最近联机时间、最近已显示版本；电量只有硬件可可靠测量时才显示。
- 首版先少量设备，不建设独立预约系统、消息队列、图数据库或通用 IoT 平台。
- 后续批量前需要安全的固件升级/回退、批量配网、失联告警、安装清单和维保流程。
